# 翻译风格规则(模板)

> 本文件是**你的风格配置**。工具只提供机制,风格由你定义。
> 改完存成 `profiles/style_rules.txt`(去掉 `.template` 后缀),程序会自动读取。
> `style_rules.txt` 已在 `.gitignore` 里 —— 你的风格不会进仓库。

---

## 怎么用

1. 复制本文件为 `profiles/style_rules.txt`
2. 按你的习惯改写下面的规则
3. 往 `profiles/glossary.txt` 里加你自己的词条
4. 有 API key 的话跑一次评测,看模型学得像不像:

```powershell
python bin/llm_translate.py --eval --limit 20
```

评测会拿你的语料当考题,量出"完全一致"的比例。**改一次规则就跑一次**,才知道有没有变好。

---

## 规则正文(下面是示例,请按你的风格改写)

# 总纲
一句话概括你的译文风格。例:**名词用街头土词,句式用书面雅语**。
- 名词层面:用口语/俚语词,不要书面语
- 句式层面:用完整书面句,动词优先四字格或双音节雅词
- 典型错误要写出来:什么样的译法你**不**接受

# 硬规则
写 5–15 条,每条给**正例**和(重要的)**反例**。
反例比正例有用 —— 模型最容易犯的错要靠反例挡住。

R1 并列/转折句式怎么处理
R2 四字格或成语的使用密度
R3 名词怎么口语化
R4 英文名词堆叠时是否补动词
R5 专有名词三分法:人名 / 品牌 / 地名分别怎么处理
R6 脏话怎么处理(去脏化?保留?抬升身份?)
R7 括号垫词、和声、ad-lib 怎么处理
R8 雅化的**分寸**:到什么程度算过头
R9 第一人称:是否按语气切换,用哪几个词
R10 歧义词(一词多义)怎么判
R11 星号遮蔽词怎么处理
R12 语序是否保留原文
R13 数字与金额:精确译还是画面化
R14 中文长度:约为英文词数的多少倍

# 输出要求
- 只输出译文,不要解释
- 一句对一句,不合并不拆分
- 标点规范(全角/半角)
- 专名是否保留原文

---

## 提示:规则空着行不行?

行。程序有三层降级:

1. **语料召回** —— 你译过的句子直接复用(不需要规则)
2. **术语表替换** —— 按 `glossary.txt` 替换词条(不需要规则)
3. **LLM 翻译** —— 需要规则,规则越具体越像你

所以**没有规则也能用**,只是第三层会退化成普通翻译。
